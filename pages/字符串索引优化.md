- >  [MySQL 实战 45 讲](https://time.geekbang.org/column/article/71492)
  > 直接创建完整索引，这样可能比较占用空间；
  创建前缀索引，节省空间，但会增加查询扫描次数，并且不能使用覆盖索引；
  倒序存储，再创建前缀索引，用于绕过字符串本身前缀的区分度不够的问题；
  创建 hash 字段索引，查询性能稳定，有额外的存储和计算消耗，跟第三种方式一样，都不支持范围扫描。
- | 字段特性 | 是否可以支持区间查找 | 索引类型 | 字段处理 |
  | --- | --- | --- | --- |
  | 短 | 是 | 完整索引 |  |
  | 长 | 是，但是需要回表（无法支持覆盖索引） | 前缀索引 | alter table t_ser add index index2(card_no(6)); |
  | 长，前缀高度重复（比如身份证号） | 否 | 倒叙索引 | reverse(card_no) |
  | 长 | 否 | hash字段索引 | card_no_hash = crc32(card_no) |
- 计算不同前缀的区分度
  ```sql
  mysql> select 
  count(distinct left(email,4)）as L4,
  count(distinct left(email,5)）as L5,
  count(distinct left(email,6)）as L6,
  count(distinct left(email,7)）as L7,
  from SUser;
  ```
