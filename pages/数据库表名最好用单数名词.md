- ## 支持 **复数** 的理由很简单：
- 表里存的是很多个用户，不是一个。
- 写SQL的时候读起来很自然。
- ## 支持 **单数** 的理由更讲究：
- 1. 从理论上说，我们定义的是一种**关系模型**。我们在描述"用户这个概念"包含哪些属性：ID、姓名、地址等等。"用户"这个概念本身是单数的，只是用这个模型可以存很多条用户数据而已。
- 2. 在SQL语句的其他地方读起来更通顺：
  
  ```sql
  SELECT id, name
  FROM user
  JOIN country ON user.country_id = country.id
  WHERE country.name = 'Canada';
  ```
  
  如果写成 `users.country_id` 反而感觉怪怪的。
- 3. 代码里的类名通常是单数（User类）。如果表名用复数，就对不上了。而且ORM框架（*比如* Rails）会自动把单词变复数，结果就会出现 `addresss` 这种奇怪的表名（address的复数拼错了）。
- 4. **有些词本来就是复数形式**。比如你有个类叫 `UserFacts`（用户信息集合），用来存年龄、喜欢的颜色这些杂七杂八的信息。那表名该叫什么？`UserFactss`？这就尴尬了。
  ```sql
  CREATE TABLE UserFacts (
      user_id INT PRIMARY KEY,
      age INT,
      favorite_color VARCHAR(50),
      ...
  );
  ```
- ## 总结
- **第4点最关键**——只要碰到一个本身就是复数的词，整套命名规则就乱套了。用单数命名，现在不会有问题，以后也不会有问题。
