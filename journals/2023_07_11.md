- 什么是 [[redis]] [[大key]]？ #小林coding #card
  id:: 64ad0c23-bf5a-4276-bbdf-2efa0eb590aa
	- 大 key 并不是指 key 的值很大，而是 key 对应的 value 很大。
	  一般而言，下面这两种情况被称为大 key：
		- String 类型的值大于 10 KB；
		- Hash、List、Set、ZSet 类型的元素的个数超过 5000个；
- [[大key]]会造成什么问题？#redis  #小林coding #card
  id:: 64ad0c6d-65dd-415c-90eb-e8ca48ddb815
	- **客户端超时阻塞**。由于 Redis 执行命令是单线程处理，然后在操作大 key 时会比较耗时，那么就会阻塞 Redis，从客户端这一视角看，就是很久很久都没有响应。#单线程处理耗时
	  **引发网络阻塞**。每次获取大 key 产生的网络流量较大，如果一个 key 的大小是 1 MB，每秒访问量为 1000，那么每秒会产生 1000MB 的流量，这对于普通千兆网卡的服务器来说是灾难性的。#网络传输耗时
	  **阻塞工作线程**。如果使用 del 删除大 key 时，会阻塞工作线程，这样就没办法处理后续的命令。#单线程删除耗时 使用[[unlink]]命令，会在另外的线程异步删除
	  **内存分布不均**。集群模型在 slot 分片均匀情况下，会出现数据和查询倾斜情况，部分有大 key 的 Redis 节点占用内存多，QPS 也会比较大。 #集群分片大小不均
- [[redis]]中并没有提供回滚机制 #card #redis事务
  id:: 64ad0c9f-1ce9-4582-8a52-ca998c1b7821
	- 虽然 Redis 提供了 DISCARD 命令，但是这个命令只能用来主动放弃事务执行，把暂存的命令队列清空，起不到回滚的效果。
