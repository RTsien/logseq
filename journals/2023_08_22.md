	- [[余弦距离]]：体现的是向量夹角，夹角越小，越相似，值越大。余弦相似度=余弦距离。适合每个向量的打分尺度不一致的场景，主要看打分的倾向，而不是绝对分值。比如根据各自电影评分，计算用户间电影兴趣相似度。
	- [[欧氏距离]]：体现的是向量顶点的绝对距离。欧式相似度=$$\frac1{1+d}$$。适合向量的打分尺度一致的场景。
	  比如根据产品付费额度，分析用户价值。
	- [[点积距离]]：直接对向量做点积运算。$$\vec a * \vec b = \sum _1 ^n a_i * b_i = |\vec a| |\vec b| cos \theta$$。长度越大，角度越小，值越大。
		- 假如对向量进行归一化处理，[[点积距离]]实际上就是[[余弦距离]][src](https://zhuanlan.zhihu.com/p/159244903)

	- 基于用户的协同过滤：用户少，物品多。向量空间是用户对所有物品的评分。
	- 基于物品的协同过滤：用户多。向量空间是所有用户对物品的评分。
		- $$Jaccard Similarity=\frac{同时喜欢两个物品的用户数（交集）}{喜欢两个物品中任意一个的用户数（并集）}$$
- 5.5.2 Wide&Deep模型 #《程序员的AI书》 推荐系统基础 P137 #card

	- Google将线性模型称为Wide模型，记住常见高频的数据组合
	- Deep通过[[Embedding]]将特征向量化，**将特征的精确匹配变为特征向量的模糊查找**
	  {{embed ((65433c65-bd7e-4de6-8ae3-887ebbb1789f))}}
	- 交叉特征cross feature，离散特征的值两两组合，变幻出更多的特征。但是如果离散特征的值种类很多，那么交叉后的特征数很多，导致特征向量非常稀疏。
		- 比如有两个离散特征：国家和语言。两个特征的可能值两两组合：中国-汉语，中国-英语，美国-汉语，美国-英语……
		- 因子分解机（[[Factorization Machine]]，FM）解决特征向量稀疏的问题
	- 为什么线性模型称为wide模型呢？ [Google WIDE&DEEP，以及Embedding - Monica AI Chat](https://monica.im/share/chat?shareId=nsl6XRQMyh0pKXmy)
		- 线性模型通常处理大量的特征输入，每个特征都有自己的权重。当我们考虑特征工程时，尤其是对类别型特征进行 one-hot 编码后，特征向量会变得非常"宽"（维度很高）。这种高维特征空间使得模型在水平方向上"展开"，因此被形象地称为"Wide"模型。
		- 在 Google 提出的 Wide & Deep 学习框架中，"Wide"模型（线性模型）与"Deep"模型（深度神经网络）形成对比：
		  "Wide"部分是一个线性模型，处理宽泛的特征组合
		  "Deep"部分是一个深度神经网络，专注于特征的泛化和抽象表示
		- 线性模型特别擅长：
		  **记忆（Memorization）**：能够学习并"记住"训练数据中出现的特定特征组合及其对应的目标值
		  **显式特征交叉**：通过特征组合（feature crossing）可以捕获特定特征组合的共现关系
		  **处理稀疏特征**：对于高维稀疏特征空间非常有效
		  例如，如果"年龄=25"和"职业=工程师"这两个特征同时出现时往往对应某个特定结果，线性模型可以通过为这种特征组合分配特定权重来"记住"这种模式。
		- ### 典型应用场景对比
			- | 特性 | Wide 模型 | Deep 模型 |
			  | ---- | ---- | ---- |
			  | 特征处理 | 显式交叉（如职业×商品类别） [2](https://github.com/ShaoQiBNU/wide_and_deep) | 隐式抽象（如用户兴趣 Embedding） [5](https://oysterqaq.com/archives/1354) |
			  | 数据需求 | 依赖高频共现数据 | 需要充足数据支持泛化 |
			  | 响应速度 | 权重解释性强，在线预测快 [4](https://zhuanlan.zhihu.com/p/74957209) | 计算复杂度较高 |
		- ### 维度对比：高维稀疏 vs 低维稠密
			- | **特征类型** | **示例** | **维度** | **数值特性** |
			  | ---- | ---- | ---- |
			  | 原始高维稀疏特征 | 用户ID、商品SKU | 百万级维度 | 0/1二值，99.9%为0 |
			  | 低维稠密Embedding | 用户向量(0.3, -1.2..) | 32-512维 | 连续实数，全非零 |
			  
			  例如在电商推荐场景：
			  原始特征：用户ID "U12345" → 百万维one-hot向量（仅第12345位为1）
			  Embedding后：转化为32维向量 [0.7,−0.3,1.2,...,0.4][0.7,−0.3,1.2,...,0.4]
		- ### 核心价值：解决三大问题
			- **维度灾难缓解**
				- 计算复杂度从 O(D)*O*(*D*) 降至 O(d)*O*(*d*)，例如D=1e6时：
				  存储需求：从1MB/样本 → 0.03MB（d=256）
				  矩阵运算量减少99.97%
			- **语义关系捕捉**
			  通过向量运算揭示隐含关系：
			  ```
			  # 经典示例：词向量关系
			  vec("国王") - vec("男人") + vec("女人") ≈ vec("女王")
			  ```
			- **迁移学习支持**
			  预训练Embedding可在不同任务间复用：
				- BERT的词向量用于文本分类
				- 用户Embedding跨场景复用（电商→视频推荐）

		- ### [[双线性分解]] #TODO 有空再深入研究
			- 双线性分解（Bilinear Factorization）是一种将大型矩阵（通常表示用户-物品交互矩阵）分解为两个较小维度矩阵的方法。这种方法常用于推荐系统（如[[协同过滤]]推荐）中，以捕捉用户和物品之间的隐含关系。
			  
			  具体来说，给定一个用户-物品交互矩阵 *R*∈R*m*×*n*，其中：
			  *m*：用户数
			  *n*：物品数
			  *R**ij*​：用户 *i* 对物品 *j* 的交互（评分、点击、购买等）
			  
			  双线性分解的目标是找到两个低维矩阵：
			- 用户矩阵 *U*∈R*m*×*d*，每行表示一个用户的低维特征向量。
			- 物品矩阵 *V*∈R*n*×*d*，每行表示一个物品的低维特征向量。
			  使得：
			  *R*≈*U**V**T*
			- #### 直观理解示例
			  假设一个电影推荐场景：
			  | 用户\电影 | 哈利波特 | 复仇者联盟 | 泰坦尼克 |
			  | ---- | ---- | ---- |
			  | 用户A | 5 | ? | 4 |
			  | 用户B | ? | 4 | 3 |
			  | 用户C | 1 | 5 | ? |
			- 原始矩阵 *R* 是稀疏的，很多评分未知。
			- 通过双线性分解，我们可以学习到用户和电影的隐含特征：
				- 用户A可能喜欢“魔幻”、“爱情”；
				- 用户B可能喜欢“动作”、“科幻”；
				- 用户C可能喜欢“动作”、不喜欢“魔幻”。
			- 最终通过 *u**i**T*​*v**j*​ 计算未知评分，预测用户偏好。
				- ❓感觉应该是*u**i*​*v**j**T*才对
