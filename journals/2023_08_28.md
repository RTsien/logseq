- [[istio]]为什么用127.0.0.6 [src](https://github.com/istio/istio/issues/29603#issuecomment-747088799) #card
  id:: 64ef0d4c-1b5e-4a9d-b8e7-949a768e411c
	- 选择127.0.0.6是因为它是Linux IPv4堆栈中合法且免费的本地IPv4地址。而且`.6`与1500`6`稍微匹配。我承认可能有其他选择。
	- ```bash
	   $ip route show table local |grep 127.0.0.0
	  local 127.0.0.0/8 dev lo proto kernel scope host src 127.0.0.1
	  ```
	- 为什么在代理未声明的端口时使用127.0.0.6，而在代理声明的端口时使用127.0.0.1？
		- 很棒的实验！简短的回答是配置简化。
		- 有些流量可能导致无限循环，而有些流量不会导致无限循环。
		- 前者是击中passthrough过滤器链的流量，istio没有在该pod端口上使用pod IP地址定义服务。127.0.0.6用于将流量标记为“入站流量”，永远不会触及出站iptables规则。
		- 后者击中k8s服务目标端口的流量具有目标地址127.0.0.1，不会导致无限循环。绑定127.0.0.6没有带来好处，因此127.0.0.1由Linux内核自动选择。理论上，我们也可以以另一个系统调用和一些额外的envoy配置为代价绑定127.0.0.6。
